# 결정 지점 체크리스트

요구사항 대화에서 자주 비어 있는 영역 목록이다. **기계적으로 전부 물어보라는 뜻이 아니다.** 기능 성격에 맞는 항목만 골라 점검하고, 관련 없는 영역은 건너뛴다.

각 항목은 "티켓이나 사용자 요청에 이미 답이 있는가?"를 먼저 확인하고, 없는 것만 질문 대상으로 남긴다.

## 입력과 출력

- 무엇을 입력으로 받는가 (형태, 필수/선택)
- 무엇을 결과로 보여주는가 (단건/목록, 정렬 기준)
- 목록이라면 개수 제한이나 더 보기가 필요한가
- 빈 결과일 때 무엇을 보여주는가

## 검증

- 무엇을 검증하는가
- 언제 검증하는가 (입력 중 / 제출 시 / 저장 직전)
- 검증에 실패하면 어떻게 알리는가 (문구, 위치, 지속 시간)
- 검증을 통과하지 못한 상태에서 다음 동작이 가능한가

## 실패와 예외

- 실패할 수 있는 지점은 어디인가
- 실패하면 사용자에게 무엇을 보여주는가
- 재시도할 수 있는가, 자동인가 수동인가
- 부분적으로 성공했을 때 어떻게 처리하는가
- 실패한 상태에서 앱을 다시 열면 무엇이 남아 있는가

## 상태 표현

- 처리 중임을 어떻게 알리는가
- 처리 중에 같은 동작을 다시 실행할 수 있는가
- 취소할 수 있는가, 취소하면 이미 진행된 것은 어떻게 되는가
- 성공했을 때 화면이 어떻게 바뀌는가

## 지속성

- 이 데이터는 앱을 껐다 켜도 남아야 하는가
- 남아야 한다면 어디에 저장하는가 (설정 파일, 사용자 데이터 디렉토리)
- 저장 실패는 어떻게 처리하는가
- 기존 데이터가 있는 상태에서 형식이 바뀌면 어떻게 되는가

## 범위와 권한

- 누가 이 기능을 쓸 수 있는가
- 접근할 수 없는 사용자에게는 무엇이 보이는가 (숨김 / 비활성 / 안내)

## 규모와 성능

- 데이터가 얼마나 많아질 수 있는가
- 얼마나 오래 걸려도 괜찮은가
- 오래 걸리면 진행률을 보여줘야 하는가

## Electron 특유 (해당할 때만)

- 이 동작은 어느 프로세스가 수행해야 하는가 (파일·네트워크는 main, 화면은 renderer)
- 창을 닫거나 앱을 종료하는 중에 이 동작이 진행 중이면 어떻게 되는가
- 여러 창이 열려 있을 때 상태를 공유하는가
- 파일 시스템에 접근한다면 경로를 사용자가 고르는가, 앱이 정하는가
- 오프라인 상태에서 동작해야 하는가

## 범위 밖

- 이번에 하지 않기로 명시적으로 정한 것은 무엇인가
- 비슷해 보이지만 포함하지 않는 것은 무엇인가

> 범위 밖 항목은 "안 물어봐서 빠진 것"과 "빼기로 정한 것"을 구분해준다. 대화 마지막에 한 번 확인한다.
